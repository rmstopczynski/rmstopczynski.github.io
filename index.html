How I Work

01

Audit before I build

Before rebuilding the nuclear outage tracker, I read the inherited codebase line by line instead of assuming a working demo meant working infrastructure — and found the "database" was a `List<T>` that reset on every restart.

02

Document the honest tradeoff

When logistic regression beat XGBoost on the manufacturing model's F1 score, I wrote that down instead of cherry-picking the result that sounded better on a resume.

03

Own the whole stack

At Jabil I evaluate governance tooling built by others. On my own time I build the same category of system end to end — ingestion, transformation, validation, and the API serving it — so I understand what that tooling actually has to get right.

04

Ship with tests, not vibes

60 dbt tests on the healthcare pipeline, a 12-case evaluation harness on the RAG assistant — every project ships with a way to prove it actually works, not just a demo that happened to run once.
